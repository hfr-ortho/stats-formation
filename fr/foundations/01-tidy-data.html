1 · Données ordonnées (tidy data)

Ce que sont des données ordonnées, comment les collecter, comment ordonner des feuilles de calcul désordonnées et comment prouver que rien n’a changé.

Dans un projet de recherche, la plus grande partie du temps sert à mettre les données en forme, pas aux statistiques. Les erreurs commises ici sont du genre dangereux : le code s’exécute, les tableaux ont l’air corrects, et les chiffres sont faux. Cette page montre comment collecter des données propres dès le départ, comment les nettoyer quand elles ne le sont pas, et comment prouver que votre nettoyage n’a rien modifié qui n’aurait pas dû l’être.

Ce que veut dire « ordonné »

Des données sont ordonnées (tidy) quand :

  1. chaque variable est une colonne,
  2. chaque observation est une ligne, et
  3. chaque type d’unité d’observation a son propre tableau.
Note💡 En clair

Un fait par cellule, une observation par ligne, et jamais deux sortes de lignes mélangées dans le même tableau. Une feuille facile à lire pour une personne est souvent difficile à analyser pour un ordinateur, et inversement. Les logiciels de statistiques veulent la seconde sorte.

Voici une feuille de PROM (mesure des résultats rapportés par le patient) typique, mais non ordonnée : une ligne par patient, avec une colonne par visite. La visite est une variable, mais elle se cache dans les noms de colonnes.

Collecter des données ordonnées

Le nettoyage le moins cher est celui que vous n’avez jamais à faire. Avant que quiconque ne dépouille un seul dossier, écrivez le dictionnaire de données : le nom, la signification, le type, les unités et les valeurs autorisées de chaque variable. Construisez ensuite la feuille de collecte à partir du dictionnaire.

Ce site propose un modèle que vous pouvez copier : templates/data-collection-template.xlsx. Il contient quatre feuilles :

  • README — les règles ci-dessous, pour la personne qui dépouille les dossiers.
  • data — une seule ligne d’en-tête, et des listes déroulantes ou des contrôles de plage sur chaque colonne sauf l’identifiant d’étude, pour que les fautes de frappe ne passent pas.
  • dictionary — la signification de chaque colonne.
  • missing_codes — ce qu’il faut saisir exactement quand une valeur ne figure pas dans le dossier.

Les règles que le modèle impose :

  1. Une ligne par intervention, une colonne par variable, une valeur par cellule.
  2. Un identifiant d’étude (le code d’étude), jamais le numéro ni le nom du patient. La clé de codage, qui relie les codes d’étude aux numéros de patient, est conservée dans un fichier séparé et sécurisé par la personne que la demande d’autorisation désigne pour cela, et qui ne participe pas au projet.
  3. Des catégories issues de listes déroulantes uniquement (pas de F ou de female mélangés).
  4. Des nombres uniquement dans les colonnes numériques ; les unités figurent dans le dictionnaire.
  5. De vraies dates, pas du texte.
  6. Manquant signifie : la valeur « Not recorded » de la liste déroulante, ou une cellule numérique ou de date vide.
  7. Ni couleurs, ni gras, ni commentaires, ni cellules fusionnées, ni lignes de titre, ni lignes de totaux.

Ordonner un classeur désordonné

Les vraies feuilles de saisie suivent rarement ces règles. Le fichier data/messy_abstraction_workbook.xlsx reprend les problèmes que nous rencontrons dans les vraies feuilles. Ouvrez-le dans Excel et regardez-le avant d’exécuter le moindre code (ses colonnes et ses données sont en anglais) :

  • deux onglets, Site A et Site B, dont les colonnes ne correspondent pas (Site B a une colonne MUA en plus, au milieu)
  • deux lignes de bandeau et une ligne d’en-têtes de groupe fusionnés au-dessus du vrai en-tête
  • une ligne TOTAL au bas de chaque onglet
  • deux colonnes Date et deux colonnes Score (PROM préopératoires et à 1 an)
  • des formats de date mélangés, des unités dans des cellules numériques, des classes ASA en chiffres romains, cinq façons d’écrire « manquant »
  • des révisions marquées uniquement par un fond rouge sur la cellule de l’identifiant d’étude (Study ID)
  • des lignes en double

Nous le corrigerons une étape à la fois. Chaque étape est assez petite pour être vérifiée. Exécutez les étapes dans l’ordre : chacune part du résultat de la précédente.

Étape 1 : lire les deux onglets comme du texte

Lisez d’abord tout comme du texte. Si vous laissez le logiciel deviner les types, il transforme 32.1 kg/m2 en valeur manquante sans prévenir, et vous ne le saurez jamais. Nous convertirons les types délibérément à l’étape 5.

  • R
  • Python
path <- "data/messy_abstraction_workbook.xlsx"

read_site <- function(sheet) {
  # skip = 3 saute les deux lignes de bandeau et la ligne des en-têtes de groupe
  raw <- read_excel(path, sheet = sheet, skip = 3, col_types = "text",
                    .name_repair = "minimal")
  names(raw) <- str_trim(names(raw))   # "Study ID " a un espace à la fin sur Site B

  # Les deux paires Date/Score : l'en-tête de groupe indique d'abord préop, puis 1 an
  names(raw)[names(raw) == "Date"]  <- c("prom_preop_date", "prom_1yr_date")
  names(raw)[names(raw) == "Score"] <- c("prom_preop", "prom_1yr")

  raw |>
    janitor::clean_names() |> # "Pt Name" devient pt_name, "Study ID" devient study_id
    mutate(site = sheet)      # retenir de quel onglet vient chaque ligne
}

import re

path = "data/messy_abstraction_workbook.xlsx"

def read_site(sheet):
    # header=3 prend la 4e ligne comme noms de colonnes (après les bandeaux et les en-têtes de groupe)
    raw = pd.read_excel(path, sheet_name=sheet, header=3, dtype=str)
    names = [str(c).strip() for c in raw.columns]   # "Study ID " a un espace à la fin sur Site B

    # pandas renomme les en-têtes répétés en "Date.1" et "Score.1"
    pairs = {"Date": "prom_preop_date", "Score": "prom_preop",
             "Date.1": "prom_1yr_date", "Score.1": "prom_1yr"}
    names = [pairs.get(n, n) for n in names]

    # "Pt Name" devient pt_name, "Study ID" devient study_id
    raw.columns = [re.sub(r"[^0-9a-z]+", "_", n.lower()).strip("_") for n in names]
    return raw.assign(site=sheet)   # retenir de quel onglet vient chaque ligne

126 lignes : 60 patients par onglet, plus 2 doublons et une ligne de totaux dans chacun. Comme nous avons empilé les onglets d’après le nom des colonnes, la colonne MUA en plus de Site B n’a rien décalé. Les lignes de Site A ont simplement mua manquant. Copier les cellules d’après leur position aurait placé les valeurs de la durée de séjour (LOS) sous le mauvais titre.

En R, nous appelons janitor::clean_names() avec le nom du package devant, au lieu de charger janitor avec library(). Charger janitor masque les fonctions chisq.test() et fisher.test() de R par les versions de janitor. Elles donnent les mêmes réponses pour des tableaux ordinaires, mais le message de masquage prête à confusion, et il devient plus difficile de savoir quelle fonction vous appelez réellement.

Astuce🔀 R ou Python : le même fichier Excel, lu différemment
  • En-têtes répétés. R (avec .name_repair = "minimal") garde les deux colonnes Date sous le nom Date. pandas renomme la seconde en Date.1.
  • Vraies dates Excel. Lues comme du texte, R donne le numéro de série Excel (42010 signifie le 6 janvier 2015). pandas donne 2015-01-06 00:00:00. L’étape 5 s’occupe des deux.

Avertissement⚠️ Attention : 999 n’est un code de valeur manquante que si votre dictionnaire le dit

Dans cette feuille, 999 signifie « manquant » dans les colonnes numériques. Dans une autre feuille, ce pourrait être une vraie valeur. Inscrivez chaque code de valeur manquante dans le dictionnaire de données avant le début de la collecte.

Étape 4 : retrouver les révisions codées par la couleur

La feuille marque les cas révisés uniquement par un fond rouge sur la cellule de l’identifiant d’étude. La plupart des logiciels qui lisent un tableur ne voient pas du tout les couleurs, et c’est exactement pourquoi la couleur ne doit jamais porter de données. Ici, il faut aller la chercher.

Étape 5 : donner à chaque colonne son vrai type

Convertissez maintenant chaque colonne de texte en ce qu’elle est réellement. Une petite fonction gère les formats de date mélangés. Chaque recodage énumère les valeurs attendues et transforme tout le reste en valeur manquante : une surprise comme U pour le sexe apparaît au lieu de devenir « Male » en silence.

  • R
  • Python
# Les dates arrivent comme numéros de série Excel ("42010"), comme dates ISO
# ("2015-04-21") ou comme texte suisse jour d'abord ("13.01.15", "13.1.2015").
# On traite les numéros de série, puis les dates ISO, puis on lit le reste
# avec le jour d'abord.
parse_messy_date <- function(x, day_first = TRUE) {
  serial <- !is.na(x) & str_detect(x, "^\\d{5}$")
  iso    <- !is.na(x) & str_detect(x, "^\\d{4}-\\d{2}-\\d{2}$")
  rest   <- !is.na(x) & !serial & !iso
  out <- as.Date(rep(NA, length(x)))
  out[serial] <- janitor::excel_numeric_to_date(as.numeric(x[serial]))
  out[iso]    <- ymd(x[iso])
  out[rest]   <- if (day_first) dmy(x[rest], quiet = TRUE) else mdy(x[rest], quiet = TRUE)
  out
}

tidy <- step3 |>
  rename(procedure_text = procedure) |>   # garder le texte brut jusqu'à ce qu'on l'ait séparé
  transmute(
    case_id      = str_trim(study_id),

import numpy as np

def number(text):
    # Le premier nombre de chaque cellule : "67 yo" -> 67, "BMI 31.2" -> 31.2
    return pd.to_numeric(text.str.extract(r"(\d+\.?\d*)")[0])

asa_roman = {"I": "1", "II": "2", "III": "3", "IV": "4"}
procedure_text = step3["procedure"]   # garder le texte brut jusqu'à ce qu'on l'ait séparé

# Chaque cellule arrive en texte : dates ISO ou dates suisses jour d'abord.
# dayfirst=True inverserait aussi les dates ISO, donc on les lit séparément.
def parse_messy_date(col, dayfirst=True):
    """Every cell arrives as text: ISO dates ("2015-04-21", and real Excel dates as
    "2015-01-06 00:00:00") or Swiss day-first dates ("13.01.15", "13.1.2015").
    dayfirst=True would also flip ISO dates, so they're read on their own."""
    iso = col.str.match(r"\d{4}-\d{2}-\d{2}", na=False)
    swiss = col.notna() & ~iso
    dates = pd.concat([pd.to_datetime(col[iso], format="ISO8601"),
                       pd.to_datetime(col[swiss], format="mixed", dayfirst=dayfirst)])
    return dates.reindex(col.index)   # retour à l'ordre des lignes ; les cellules vides restent manquantes (NaT)

Astuce🔀 R ou Python : les dates

R a besoin d’une étape séparée pour les numéros de série Excel (janitor::excel_numeric_to_date()). pandas a déjà transformé ces cellules en texte date-heure (2015-01-06 00:00:00), que sa fonction parse_messy_date() lit avec les autres dates ISO. Les deux lisent "13.01.15" avec le jour d’abord : c’est le style suisse, celui des feuilles de l’HFR. Les deux lisent les dates ISO séparément, parce que dayfirst=True de pandas les inverserait aussi (2015-11-02 deviendrait le 11 février).

À quoi ressemble un contrôle qui échoue

Supposons que nous ayons lu par erreur les dates d’opération avec le mois d’abord (style américain, comme le font beaucoup d’exemples en ligne). Rien ne plante. Deux contrôles le détectent : un décompte des valeurs manquantes (contrôle 2, appliqué aux dates) et un nouveau contrôle de logique, qui vérifie que chaque PROM préopératoire tombe dans le mois qui précède l’opération.

  • R
  • Python
wrong <- parse_messy_date(step3$dos, day_first = FALSE)   # l'erreur
preop <- parse_messy_date(step3$prom_preop_date)

outside_window <- function(surgery) {
  days_before <- as.numeric(surgery - preop)
  sum(days_before < 0 | days_before > 31, na.rm = TRUE)
}
c(missing_correct     = sum(is.na(tidy$surgery_date)),
  missing_month_first = sum(is.na(wrong)),
  window_correct      = outside_window(parse_messy_date(step3$dos)),
  window_month_first  = outside_window(wrong))
    missing_correct missing_month_first      window_correct  window_month_first 
                  0                  30                   0                  12 
wrong = parse_messy_date(step3["dos"], dayfirst=False)   # l'erreur
preop = parse_messy_date(step3["prom_preop_date"])

def outside_window(surgery):
    days_before = (surgery - preop).dt.days
    return int(((days_before < 0) | (days_before > 31)).sum())

print(pd.Series({
    "missing_correct": tidy["surgery_date"].isna().sum(),
    "missing_month_first": wrong.isna().sum(),
    "window_correct": outside_window(parse_messy_date(step3["dos"])),
    "window_month_first": outside_window(wrong),
}))

Avec la lecture correcte, rien ne manque et chaque PROM préopératoire tombe dans sa fenêtre de temps. Les versions avec le mois d’abord se trompent de manières différentes :

  • R ne peut pas lire avec le mois d’abord des dates comme "13.01.15" (il n’y a pas de 13e mois) : 30 dates d’opération deviennent donc manquantes. D’autres, comme "04.03.24", sont lues « avec succès » comme le 3 avril au lieu du 4 mars, et le contrôle de la fenêtre temporelle en signale 12.
  • pandas ne renvoie jamais de date manquante ici : quand le mois d’abord est impossible, il passe discrètement au jour d’abord. "13.01.15" sort donc juste par chance, alors que "04.03.24" devient le 3 avril. Seul le contrôle de la fenêtre temporelle le remarque : il signale 12 dates.
Avertissement⚠️ Attention : un seul contrôle ne suffit jamais

Ne lisez jamais une colonne qui mélange des formats avec un seul réglage : lisez chaque format séparément, comme le fait parse_messy_date(). Remarquez aussi que le décompte des valeurs manquantes a repéré ce bogue en R mais pas en Python, alors que le contrôle de logique l’a repéré dans les deux. Faites tous les contrôles à chaque fois : ils détectent des erreurs différentes.
