# HFR Ortho Statistics Tutorials — Design Spec

**Date:** 2026-10-06
**Status:** Approved in brainstorming; awaiting written-spec review
**Repo:** `hfr-ortho/stats-formation` (public)
**Site:** `https://hfr-ortho.github.io/stats-formation/` (`/en/`, `/de/`, `/fr/`)
**Derived from:** `Total-Joint-Specialists/example-stats-analysis` at `94d62e9`
(its spec, `docs/superpowers/specs/2026-10-05-tjs-stats-tutorials-design.md`,
still defines the tutorial conventions; this spec records what HFR changes)

---

## 1. Purpose

A public tutorial website plus repository that teaches HFR Ortho residents,
research assistants and medical students doing their master's thesis at HFR
Ortho how to prepare data and run the statistical analyses used in orthopaedic
research, in **R, Python, or both**, and in **English, German or French**.

It is the TJS Statistics Tutorials site, rebranded for HFR (Hôpital
fribourgeois / freiburger spital), adapted to Swiss rules and practice, later
broadened beyond arthroplasty, and translated.

**Success looks like:** a reader starting a real HFR project can do everything
the TJS spec §1 lists (find the test, understand it, adapt the code, write the
Methods and Results sentences, check their tidied data), reading the
explanations in the language they're most comfortable in, and knowing the Swiss
rules for handling real patient data.

## 2. Decisions made in brainstorming

| Topic | Decision |
|------|------|
| Relationship to TJS | **Independent copy that keeps TJS's git history.** Remote `tjs` is fetch-only (push URL disabled). TJS fixes are carried over by hand (`git fetch tjs` + cherry-pick) when wanted; nothing syncs automatically. |
| Hosting | **Public repo + GitHub Pages**, like TJS. The `hfr-ortho` org is on the free plan, where Pages can't publish from a private repo. All data are synthetic, so public is safe. This is a deliberate exception to the org's "every repo is private" convention. |
| Content | **Adapt the TJS-specific parts** (sub-project 1) **and broaden the examples** to trauma, sports & arthroscopy, joint preservation, and foot & ankle, alongside hip and knee arthroplasty (sub-project 2). |
| Languages | **English, German, French.** Translated: prose, headings, callouts, exercises, code comments. Kept in English in every language: code, variable names, data, outputs, and the example Methods/Results sentences (HFR manuscripts are written in English; the German and French pages explain those sentences in their own language). |
| Language architecture | **Language folders in one Quarto project**: `en/`, `de/`, `fr/` with identical file names, one sidebar per language, a small switcher script. One `quarto render`, one `_freeze/`, CI unchanged. Verified in a throwaway spike with Quarto 1.9.37. |
| Branding | The vector HFR mark from h-fr.ch, in white on a navy (`#103379`) top bar, in both themes; blue `#006DB5` for links and accents. Official files from HFR communications replace it later if they become available. |
| Order | **1** bootstrap (English) → **2** broaden examples (English) → **3** French → **4** German. Translation happens once, on finished English. |
| Licenses | Unchanged: text, figures and data CC BY 4.0; code MIT. TJS copyright kept, HFR adaptations added, TJS credited (§4.1). |

## 4. Sub-project 1: Bootstrap

git remote add tjs https://github.com/Total-Joint-Specialists/example-stats-analysis.git
git remote set-url --push tjs DISABLED   # a push can never reach TJS

### 4.2 Layout

```
_quarto.yml            site config: three sidebars, shared top bar, theme
index.qmd              root page: sends visitors to their language (§4.3)
lang-switch.html       the switcher script, included on every page
en/                    every page, as on the TJS site
  _metadata.yml        lang: en
  index.qmd  choose-a-test.qmd  tests-a-z.qmd
  getting-started/  foundations/  catalog/  survival/  beyond/  report/
de/                    same file names; translated home, stubs elsewhere
  _metadata.yml        lang: de
fr/                    same file names; translated home, stubs elsewhere
  _metadata.yml        lang: fr
theme/                 hfr-light.scss, hfr-dark.scss
images/                hfr-mark-white.svg (top bar), hfr-icon.svg (favicon)
scripts/               check_setup.R, check_setup.py (moved from getting-started/)
R/  data/  data-raw/  templates/  tests/  scratch/  renv/   unchanged locations
```

- **Code paths don't change.** `execute-dir: project` runs every page from the
  repo root, so pages under `en/` still read `data/cohort.csv` and
  `source("R/check_agree.R")`. What readers copy and run from the repo root is
  unchanged.
- **Setup check scripts** move to `scripts/` so there's one copy, not three.
  The setup page, `tests/testthat/test-check_setup.R`,
  `tests/python/test_check_setup.py` and `tests/site/test_getting_started.py`
  use the new paths (`Rscript scripts/check_setup.R`,
  `uv run python scripts/check_setup.py`).
- **Relative links between pages don't change**, because the whole tree moves
  together. Links that leave the tree (to repo files on GitHub) are checked by
  lychee.
- TJS's `images/tjs-*.png` are removed.

### 4.3 How the three languages work

**Language metadata.** Each language folder's `_metadata.yml` sets `lang`. Quarto
then writes `<html lang="…">` and translates its own labels ("On this page" →
"Auf dieser Seite" / "Sur cette page", search, sidebar toggles, copy buttons,
callout titles).

**Render list.** `_quarto.yml` lists `index.qmd` and each language's folders
(`en/*.qmd`, `en/getting-started/*.qmd`, …, `de/…`, `fr/…`).

**Sidebars.** `website.sidebar` is a list of three sidebars with `id: en`, `de`,
`fr`. Quarto shows the sidebar that contains the current page. Each has the
same structure as TJS's sidebar, with these labels:

| English | Deutsch | Français |
|------|------|------|
| Home | Startseite | Accueil |
| Choose a test | Test auswählen | Choisir un test |
| Tests A–Z | Tests A–Z | Tests de A à Z |
| Getting started | Erste Schritte | Premiers pas |
| Part 1 · Foundations | Teil 1 · Grundlagen | Partie 1 · Fondements |
| Part 2 · Test catalog | Teil 2 · Testkatalog | Partie 2 · Catalogue des tests |
| Part 3 · Survival analysis | Teil 3 · Überlebenszeitanalyse | Partie 3 · Analyse de survie |
| Part 4 · Beyond the table | Teil 4 · Über die Tabelle hinaus | Partie 4 · Au-delà du tableau |
| Part 5 · Putting it together | Teil 5 · Alles zusammen | Partie 5 · Synthèse |

These are provisional; the glossary in sub-projects 3 and 4 may revise them.

The logo lives in the top bar, not the sidebars: Quarto 1.9.37 adjusts a
sidebar logo's path for the page's folder depth only in the *first* sidebar,
so a German or French sidebar logo would be a broken image (found in the
spike). Docked sidebars also hide their own titles when there is a top bar, so
the sidebars carry no title.

**Top bar** (shared by every page, so it must work in every language): the
HFR mark and `navbar.title: "HFR Ortho"` on the left; on the right, `EN` `DE` `FR` links and
the GitHub icon. TJS's text links (Home, Getting started, Choose a test,
Tests A–Z) are already at the top of each sidebar and leave the top bar.
`website.title` is `"HFR Ortho Stats"` (the browser-tab suffix).

**Switcher** (`lang-switch.html`, added with `include-after-body`). The `EN`
`DE` `FR` top-bar links are static links to each language's home page, so they
work without JavaScript and lychee checks them. The script:

1. finds the current language from the first path segment below the site root;
2. rewrites the three links to the same page in the other language, keeping
   the `#section` part;
3. marks the current language (`aria-current="true"`);
4. points the "HFR Ortho" title at the current language's home;
5. stores a manual choice in `localStorage` (inside `try/catch`; the site works
   without it).

Because file names are identical across languages, step 2 is a path swap.

**Fixed section IDs.** The switcher keeps `#section`, so a linked-to section
must have the same ID in every language. Auto-generated IDs come from the
heading text and would differ in German or French. Every heading that any link
points to therefore carries an explicit English ID (`## Mann-Whitney U test
{#mann-whitney}`), and translated pages keep it. Most TJS headings that
`choose-a-test.qmd` and `tests-a-z.qmd` link to already have one; sub-project 1
adds the rest, and a test enforces it (§4.6).

**Root page** (`index.qmd`, `sidebar: false`). Three plain links (English ·
Deutsch · Français) and a short script that redirects to the stored choice,
else to the first browser language among `en`, `de`, `fr`, else to `en/`.

**Stubs.** Until sub-projects 3 and 4, every German and French page except the
home page is a stub, so the switcher never reaches a missing page:

- title in that language plus "(in Vorbereitung)" / "(en préparation)"
  (TJS rule 7's "(coming soon)", localized);
- a `.coming-soon` callout in that language saying the page isn't translated
  yet, with a link to the English page;
- no code, so no `engine` line.

The German and French home pages are translated in full in sub-project 1
(they're short), with their cards linking to the stubs.

**Search.** One index covers all three languages. Each result shows its
language folder in the link. Filtering results to the current language waits
for sub-project 3, when there is translated text to search.

**Frozen results.** `_freeze/` is keyed by page path, so every English page
runs once, in full, after the move. With the same seeds every number must come
out identical; the prose guards and agreement checks verify this. From
sub-projects 3–4, each language's pages run their own code (about three times
the local render time; `_freeze/` grows from about 7 MB to about 21 MB). CI
still never runs R or Python.

### 4.5 HFR content adaptation (English)

#### 4.5.1 "Working with real HFR data" (`en/getting-started/real-data.qmd`)

Replaces "Working with real TJS data". Same skeleton and the same "one rule"
callout; Swiss content drawn from the HFR Ortho wiki
(`topics/issue-tag-data-protection-dpo`, `topics/issue-tag-retrospective-data-use`,
`institutions/github-hfr-ortho`):

1. **The one rule.** Unchanged: patient data never goes into a git repository;
   this repository is public.
2. **The Swiss rules.** Replaces HIPAA's 18 identifiers:
   - research on health data falls under the Human Research Act and its
     Ordinance (HRA/HRO · HFG/HFV · LRH/ORH), approved by the cantonal ethics
     committee (CER-VD for HFR) with a BASEC number, *before* any data are
     touched;
   - personal data fall under the revised Federal Act on Data Protection
     (nFADP · nDSG · nLPD);
   - **coded, not anonymous:** HFR studies work with *coded* data. The project
     lead keeps the code key, separately from the data and never in a
     repository. "Anonymous" is a different legal category; don't use the
     word for coded data;
   - **general consent:** only patients with general consent on file, unless
     the ethics committee approved otherwise (HRA Art. 34). Patients who
     refused are never included and never contacted.
3. **Identifiers and quasi-identifiers.** Direct identifiers: name, date of
   birth, address, phone, email, AHV/AVS number, HFR patient and case numbers,
   implant serial and lot numbers, photographs. Quasi-identifiers: in a small
   cohort, age + sex + surgery date + hospital can identify a patient. Coarsen
   them (age bands, surgery month or year, "a Swiss regional hospital").
4. **HFR traps.** TJS's generic traps (surgery dates, ages over 89, study IDs
   built from initials, numbers hidden in file names, implant stickers, DICOM
   headers and burned-in text, free-text notes, screenshots of the patient
   record), with AHV/AVS and HFR patient numbers added.
5. **Where HFR data lives.** Project repositories live in the private
   `hfr-ortho` GitHub organization. Patient data sit only in git-ignored
   folders (`data/raw/`, `db/`, `exports/`) that are in `.gitignore` before the
   first commit. Only aggregate results leave: tables, figures, model output,
   with small cells hidden if the protocol requires it. The storage location
   for study data is one line Doc supplies (§4.8).
6. **How HFR projects handle data in code.** TJS's three rules, unchanged
   (read as text first, match columns by name, check what you changed).
7. **AI tools.** Unchanged in substance: never paste real patient data into an
   AI tool or website unless HFR confirms the tool is approved for patient
   data.
8. **Before every commit.** Unchanged.
9. **If something goes wrong.** Stop; tell the project lead right away; the
   history has to be purged and the incident may have to be reported to HFR's
   data protection officer.

The page goes public only after Doc's review (§4.7).

#### 4.5.2 Swiss dates in the messy workbook and page 1

- `data-raw/R/gen_messy_workbook.R`: `fmt_date_text()` writes day-first text
  dates (`13.01.15`, `13.1.2015`) in place of month-first ones; Excel serial
  numbers and ISO dates stay. The banner's "Last updated" becomes
  `15.01.2026`. The style draws use the same random numbers, so every tidy
  dataset (`cohort.csv`, …) stays byte-identical; only
  `messy_abstraction_workbook.xlsx`, its answer key and `CHECKSUMS.md5` change.
- `en/foundations/01-tidy-data.qmd`: both languages parse ISO dates
  (`2015-04-21`) on their own and read only the dotted dates day-first:
  `lubridate::dmy()` in R, `dayfirst=True` in pandas. The page already teaches
  that pandas' `dayfirst=True` also flips ISO dates, so it is never applied to
  the whole mixed column. The 🔀 dates box says day-first is Swiss style. The
  "parsed wrong by mistake" example becomes *month-first (US style) by
  mistake*; its checks still catch it, and the numbers quoted about it are
  re-read from the new output.
- `just data` regenerates the files and re-renders the pages that read them.

## 5. Sub-project 2 outline: broaden the examples (English)

Designed in full in `docs/superpowers/specs/2026-10-06-hfr-sp2-broaden-examples-design.md`,
which replaces this outline where they differ.

- **New synthetic datasets**, each with a generator in `data-raw/R/`, a seed, a
  codebook, R and Python tests and the TJS privacy rules:
  - *trauma:* a hip fracture cohort (time to surgery, 30-day and 1-year
    mortality, length of stay, mobility);
  - *foot & ankle:* an immobilization RCT for a midfoot or ankle injury, with
    repeated scores and union;
  - *sports & arthroscopy:* ACL reconstruction (graft type, KOOS, Tegner,
    return to sport, graft failure);
  - *joint preservation:* radiographic readings by 2 raters × 2 sessions
    (alpha angle, tibial slope, femoral torsion), for the agreement page.
- **Arthroplasty instruments follow HFR's PROM databank**: it already uses
  HOOS JR and KOOS JR, so they stay; VR-12 becomes PROMIS-29+2 physical
  function and THA cases gain the Oxford Hip Score; discharge is home or to a
  rehabilitation clinic. (The earlier assumption of Oxford scores and EQ-5D-5L
  replacing HOOS JR/KOOS JR is withdrawn; see the addendum.)
- **Each catalog section uses the dataset that fits its question best**; every
  area appears on at least three pages. Table 1 and the example report each
  stay one coherent study.
- Every changed page is re-rendered and re-checked (agreement checks, prose
  guards, Results conventions).

## 6. Sub-projects 3–4 outline: French, then German

- **Glossary first.** `docs/glossary.csv` (English, German, French, notes) so a
  term is translated the same way everywhere; it may revise §4.3's labels.
- **Conventions.**
  - Swiss Standard German: "ss", never "ß".
  - Numbers in prose keep the decimal point in every language, matching the
    code output and the English report sentences.
  - Code, variable names, data, outputs and Methods/Results sentences stay in
    English; the page explains them in its own language.
  - Fixed section IDs stay English.
- **Per page:** translate → render → tests → review by a native speaker. Tests
  added for translated pages:
  - the R and Python chunks are identical to the English page once comments
    are stripped;
  - the same explicit section IDs;
  - the prose guard checks the same numbers;
  - catalog anatomy with the translated step headings.
- **Search** is filtered to the current language (sub-project 3).

## 7. Risks

| Risk | Mitigation |
|------|------|
| Translation volume (about 83,000 words, twice) | Glossary first; page by page; code-parity tests make sure translation never changes code; native review per part |
| Public use of the HFR logo without approval | Doc decides on communications sign-off before the repo goes public (§4.7) |
| Legal accuracy of the real-data page | Doc's review, possibly with the data protection officer, before publishing |
| A Quarto update changes sidebar selection or breaks the switcher | Quarto pinned at 1.9.37 in CI; the language tests catch a wrong sidebar or missing switcher |
| Divergence from TJS | TJS history kept; fixes carried over by cherry-pick; each carried-over prose change also needs re-translation once sub-projects 3–4 are done |
| `_freeze/` triples | About 21 MB; acceptable for a git repo |

## 8. Out of scope

- Translating code, variable names, outputs or Methods/Results sentences.
- Italian or other languages.
- Automatic syncing with TJS.
- Hosting on the HFR intranet or behind a login.
- Translating TJS's `docs/superpowers/` history.
